# Marketplace implementation

Status: verified catalog/publishing domain, directory Capability and a runnable
public HTTP read Host with browse/detail pages.
Not a deployed marketplace.

`catalog/` is an independently buildable private Rust package. It owns signed
release identity, bounded search/exact selection, and the SQLite curated
publishing domain. It is intended to be private implementation inside the
marketplace directory Plugin; it does not yet register a Plugin factory or
provide a public Capability. Console Shell has no dependency on it.

`directory/` supplies a generated native Plugin factory and the initial
`lenso.marketplace.directory@1` read role. Its read-only projection opens an
existing database, returns committed signed snapshots, and never creates
publisher state or handles signing keys. Rust and TypeScript projections have
a build-time freshness gate. These packages remain unpublished.

Implemented:

- Ed25519 signatures over domain-separated exact payload bytes, with configured
  catalog/key trust and bounded validity;
- checkpoints rejecting snapshot rollback, same-revision equivocation and
  replacement of a previously observed release, including after temporary omission;
- namespace ownership, immutable submission, digest-bound reviewer approval,
  atomic publication/snapshot persistence and audit records;
- archive size/digest checks and identity comparison against the existing
  `lenso-plugin-bundle` verifier; canonical identity validation from `lenso-cli`;
- listed/yanked/revoked selection semantics and deterministic bounded search;
- Rust/Node signature interoperability and real Process Plugin build, invocation,
  packaging, submission, review, restart and discovery acceptance.

The `fixtures/echo` project is generated by the installed CLI and pins its SDK
sources. It is test-only, uses a trusted Process implementation, and is not an
official marketplace release. Synthetic source/publisher metadata in acceptance
tests is explicitly test data, not a provenance claim.

## Signature contract (private draft)

Envelope fields are `key_id`, `payload_base64`, `signature_base64`. The payload is
a strict UTF-8 JSON `Snapshot`; duplicate typed fields and unknown fields fail.
Both encodings use padded standard Base64. The signature is Ed25519 over:

```text
UTF8("lenso.marketplace.snapshot.v1") || 0x00 || UTF8(key_id) || 0x00 || payload_bytes
```

Payload bytes are preserved exactly. Verifiers must not reserialize JSON before
signature verification. `key_id` cannot contain control characters. There is no
network-provided public key inside the envelope. SHA-256 digests use lowercase
hex with the `sha256:` prefix. Times are integer Unix seconds; validity is at
most seven days. Envelope size is at most 4 MiB; there are at most 4096 releases.
An exact release has one archive which may contain several implementations.

The committed conformance key is deterministic TEST DATA. Production bootstrap,
key storage/rotation and public schema compatibility require review before a
release. The caller must persist the checkpoint atomically with the accepted
snapshot. `VerifiedCache` supplies this SQLite transaction for the Web consumer.
Freshness is checked again on selection. Expired snapshots cannot admit installs.

## Remaining integration gates

1. The source-owned bounded archive API is implemented in CLI worktree
   `feat/verified-plugin-archive`, but not released. `Directory::submit`
   accepts only an ingestion-owned private extraction of the checked archive;
   it must not be exposed as an HTTP endpoint accepting arbitrary directory paths.
   Source integration verifies the CLI-owned archive-to-extraction handoff;
   production integration must use a released CLI API.
2. Auth-derived actors and authenticated HTTP publishing. Current reviewer and
   namespace checks are domain authorization; passing a string is not authentication.
3. Revisioned changes-requested/resubmission, withdrawal/advisory operations,
   namespace administration and snapshot refresh policy. Current v1 submissions
   are immutable, and conflicting content requires a new exact version.
4. Console contribution and remote production directory deployment. Public
   browse/detail pages are implemented and verified against the local fixture Host.
5. Target-bound remote proposal/apply/receipt integration and upgrade proof. Current
   Process invocation proves the fixture, not installation into a running Agent.

Publish is serialized with an expected catalog revision; uncertain callers read
the persisted result before retrying. Private SQLite schema is not a published
storage contract. No production migration, remote download, deployment, key
issuance, or user-target mutation is performed by this foundation.

## Public HTTP read Host

`web/` owns search and exact-release HTTP contributions and its verified cache.
It reads the directory exclusively through its Plan-bound Capability. `app/`
owns the Plugin Root, Host Catalog, binding and lifecycle assembly. Neither has
a Console Shell dependency. The directory publisher database must already exist;
the read service never initializes publisher state or accepts a signing key.

```sh
pnpm marketplace:build
"$CARGO" run --locked --manifest-path plugins/marketplace/app/Cargo.toml -- \
  --app-root /absolute/path/to/marketplace-app \
  --directory-database /absolute/path/to/published-directory.sqlite3 \
  --catalog-id YOUR_CATALOG_ID --key-id YOUR_KEY_ID \
  --public-key-hex YOUR_64_CHARACTER_ED25519_PUBLIC_KEY
```

Routes:

- `GET /api/marketplace/v1/plugins?q=echo&offset=0&limit=30`
  supports exact `publisher` and `license` filters and up to 50 comma-separated
  `ids` (`plugin_id@version`). Filters apply before pagination; `total` counts
  matching releases. Publisher/license facets cover the whole listed catalog.
- `GET /api/marketplace/v1/plugins/{plugin_id}/{version}`

No catalog, failed verification, or expired data returns a recoverable HTTP 503.
A runtime-unavailable directory may use a still-valid previously verified cache;
invalid fresh responses never silently fall back. Cache checkpoint and envelope
commit together, survive restart, and are rechecked against current trust and time.
The JSON detail response includes availability; it does not authorize installation.

The real HTTP test starts a resolved App through Kernel and Web Ingress, proves
unpublished-to-published and invalid-signature-to-valid recovery without restart,
query validation and missing
exact-release responses. Disabling the only Web provider removes all routes;
the dedicated Host then rejects startup because Web Ingress requires a route.
It does not silently preserve an old route table. This test uses an empty signed
catalog and does not constitute rendered UI or authenticated publisher acceptance.

## Browser acceptance

The independent page at `/` supports bounded search, exact-version details,
reloadable links, publisher/license filters, a publisher directory, local saved
releases (at most 50), a developer guide, pagination, light/dark themes and recoverable
failure states. It uses `@lenso/ui` controls and `@lenso/tokens`; it does not import
Console business code. The API and fixed static asset routes belong to the same
removable Web Plugin. Source links come from verified release metadata. There is
no installation or publishing button before those workflows exist.

Build from the repository root with `pnpm marketplace:build` before Cargo checks.
The Web build script checks a source/lockfile fingerprint and rejects stale or
missing assets. Build output is ignored; CI builds it from the frozen dependency
lock. Static assets use revalidation rather than immutable caching at fixed URLs.

```sh
CARGO=/Users/leosouthey/Projects/framework/.lenso-tools/bin/lenso-cargo \
  bash plugins/marketplace/verify-browser.sh
```

Requires the installed Lenso CLI and Playwright Chromium. This script builds and
packs the real Echo Process fixture, submits/reviews/publishes it to a temporary
SQLite directory, starts a real Kernel/Web Ingress Host and drives the browser.
It removes its server and temporary files on exit. An optional
`MARKETPLACE_SCREENSHOTS=/absolute/existing/directory` saves screenshots outside
source. The test key, publisher and source metadata are explicitly fixture data;
the directory expires after one hour. Browser failure injection tests retry and
missing-data presentation without changing the publisher database.

Browser checks cover search, filtered empty state, clear-filter navigation,
exact-detail reload, keyboard focus and stable hover geometry, dark narrow detail
wrapping and 503 retry recovery. See `ui-review.md` for reviewed states and limits.

Saved releases are browser-local bookmarks, not installation state. The global
search supports Command/Ctrl+K. Publisher facets come from verified listed releases;
there are no fabricated categories, ratings, download counts or featured rankings.
The asset CSP permits the exact Base UI scrollbar stylesheet hash; dependency
updates must pass browser checks without widening inline-style permissions.


The browser is split into route, request, saved-state and presentation modules.
The catalog and release detail are separate views at all sizes. Returning restores
the catalog position and focus. Same-origin navigation uses browser history without
replacing the document. Catalog and selected-release requests have independent
lifecycles; stale detail responses are aborted and ignored. Browser acceptance
includes explicit multi-release presentation fixtures in addition to the real
signed Echo fixture. See `ui-review.md` for the current design and test scope.

A release may include `description`, publisher-authored plain text with paragraph
breaks. The field is optional for existing catalogs, is limited to 16 KiB, rejects
unsupported control characters, and participates in the signed payload and review
proposal. The Web Plugin renders it as text, never HTML; without it, the overview
uses the release summary. This does not add Markdown, remote media or installation
authority.

## Catalog uses Lenso UI

Catalog consumes the existing published `@lenso/ui` components and
`@lenso/tokens/styles.css`. Buttons, text fields, selects, disclosures and content
states come from the component library. Colors, typography, spacing, radii and
focus colors follow its semantic token contract.

Catalog owns its page composition in `web/ui/app.tsx`, `components.tsx` and
`catalog-layout.stylex.ts`, together with routing, catalog data and bookmarks.
No new Lenso UI component, Recipe, registry entry or documentation page is required.

`/?catalog=sample` supplies explicitly labeled sample content; `/` reads the signed
catalog. Neither route installs plugins. See `ui-review.md` for verification.

## Exact-release installation handoff (source proof)

`verify-archive-handoff.sh` now verifies publication and signed exact selection,
binds archive bytes plus Plugin/version/manifest identity through the pending CLI
`read_release` API, and prepares/commits into an isolated authoring root using
Host admission. Use an archive packed by that CLI checkout; valid older archives
may use an incompatible target vocabulary. No UI or running Agent is mutated.

The CLI source proof separately checks canceled previews, wrong release fields,
substituted staging data, preserved installed bytes and an admitted replacement.
This is the verified-artifact-to-candidate boundary. It is not remote acquisition,
user approval, online Generation readiness, durable receipts or a completed
Marketplace installation/update flow. The public preview remains browse-only.

Validation for this handoff: 59 CLI library tests passed with the real-archive
ignored tests explicitly enabled; no-default-features library/test Clippy passed
with warnings denied; the signed-directory-to-authoring-root source handoff
passed against the current CLI-packed Echo archive. The update fixture changes
release metadata while retaining the executable; no new online behavior is claimed.

The pending CLI source also provides `PluginArchiveDownloadPolicy` for explicitly
allowed HTTPS origins. It rejects redirects, proxies, private/mixed DNS answers,
invalid TLS, unbounded bodies and transport identity changes before yielding a
verified archive. Local HTTPS tests exercise the transport with the CLI-packed
Echo artifact. This completes the transport primitive, not Agent's remote
proposal/receipt integration. No permanent sibling source dependency is added.
